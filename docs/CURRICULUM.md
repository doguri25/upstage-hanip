# 업스테이지한입 커리큘럼 (5과정 16단원 · 트랙 A 중심)

대상: 코딩한입·커서한입을 공부한 정보 교사. 목표: 업스테이지·팀모노리스·한국컴퓨터교육학회 **기반연수(2일·15차시)를 이해하고 실습을 끝까지 해내기** → 연수에서 만든 도구로 **공모전·해커톤 출전**.
단원마다 레슨 5개(L1~L5) + 헷갈림 퀴즈 2개(QA·QB) + 진짜 실습 미션(M1) + 형성평가(T1). 규칙은 `SPEC.md`, 사실은 `docs/FACTS.md`.

연습 폴더 `upstage-lab`이 단원마다 자란다:
`hello_solar.py`(c1u3) → `parse.py`(c2u1) → `extract.py`·`questions.json`(c2u2) → `chunks.json`·`search.py`(c2u3) → `helper.py`(c3u1) → `app.py`(c3u2) → `guard.py`(c3u3) → `grader/`(c4u1) → `tutor.py`(c4u2) → 루브릭·교사 화면 완성(c4u3) → (선택) `study_bot/`(c4u4) → `agent.py`(c5u1) → `team.py`(c5u2) → 대회용 저장소(c5u3).

- L3 **업스테이지와 Solar 가족**: `solar-pro4`·`solar-mini4`, Document Parse, Information Extract, 임베딩, Studio. 별칭(`solar-pro4`)과 버전 이름(`solar-pro4-260806`), 종료 일정 읽기(`solar-pro3` 2026-10-30 종료 → 옛 예제 조심).

### c1u2 · Solar로 보는 LLM의 원리 (1일차 13:00 「Solar로 보는 LLM의 원리」)
- L1 **다음 토큰 맞히기**: 토큰(글 조각), 확률 분포, 한 조각씩 이어 쓰기, 한국어 토큰 수 감각, 토큰 = 비용·속도.
- L2 **메시지와 역할, 컨텍스트**: system·user·assistant, API는 기억하지 않음(대화를 매번 다 보냄), 컨텍스트 창(512K), 길수록 돈·시간.
- QA 헷갈림: 토큰 vs 글자 / system vs user / 컨텍스트 창 vs 학습 데이터.
- L3 **temperature·top_p·max_tokens**: 표집, 낮으면 일정·높으면 다양, `finish_reason="length"`, 수업 쓰임(채점·추출은 낮게, 아이디어는 높게). 연습장(py): 점수에 temperature를 나눠 확률이 어떻게 바뀌는지 `math.exp`로 계산.
- L4 **추론(reasoning) 모드**: `reasoning_effort` 값들, 추론 토큰도 max_tokens에 들어감, 느려지고 비싸짐, 문서끼리 기본값이 달라 늘 직접 적기, 언제 켜고 끄나.
- QB 헷갈림: temperature vs reasoning_effort / max_tokens vs 컨텍스트 / 추론 글(reasoning) vs 답(content).
- L5 **환각과 한계**: 그럴듯한 틀린 답, 학습 데이터 기준 시점, 계산·최신 정보 약점, 근거 자료를 주면 나아짐(→ RAG 예고), 확인 습관.
- M1 Playground에서 temperature 실험, 같은 질문 3번 비교, 환각 유도 질문 기록, 토큰 수 어림, 연수 질문 메모.

## 과정 2 · 수업자료를 데이터로

### c2u1 · Document Parse로 수업자료 읽히기 (1일차 14:00 「수업자료를 데이터로」)
- L1 **왜 파싱하나**: PDF는 사람 눈용, 복사하면 표가 깨지고 순서가 섞임, LLM은 구조 있는 글이 필요. 학습지·교과서 쪽·시험지·HWP 공문.
- L2 **Playground에서 해 보기**(모의 화면: 파일 올리기 → 요소 강조 → Markdown/HTML 보기).
- QA 헷갈림: OCR vs 파싱 / HTML vs Markdown vs text / standard vs enhanced.
- L3 **요소와 카테고리**: 12가지, `heading1`·`table`·`figure`·`chart`·`equation`(LaTeX) 등, 좌표는 비율, 머리말·꼬리말.
- L4 **parse.py**: FACTS 5절 표준 코드, `ocr="force"`(스캔본), `mode`와 비용, 동기 100쪽·비동기, 지원 형식(HWP·HWPX), 50MB.
- QB 헷갈림: 동기 vs 비동기 / `output_formats` vs `mode` / `content.markdown` vs `elements`.
- L5 **결과 다듬기**: `elements`에서 header·footer 빼기, 표만 모으기, 쪽 번호 달기, `data/*.md`로 저장. 연습장(py): 흉내 낸 elements 목록 다루기.
- M1 Playground에 내 수업자료 → parse.py로 markdown 저장 → 스캔본 ocr 비교 → 에이전트에게 머리말 걸러내기 부탁 → 비용 확인.

### c2u2 · Information Extract로 문항·정답 뽑기 (1일차 14:00, 2일차 A 11:00 「문제·정답 데이터 구성」)
- L1 **파싱 vs 추출**: 전체 글 vs 원하는 칸만, 스키마 = 빈 서식. 학습지 → `[{번호, 문항, 보기, 정답, 배점}]`.
- L2 **스키마 설계**: JSON Schema 기초, `type`·`description`, 첫 단계 규칙, 배열 안 object. 연습장(md 또는 py): 스키마 고쳐 보기.
- QA 헷갈림: string vs array / description의 역할 / 첫 단계 object 금지.
- L3 **extract.py**: FACTS 6절, base64, `response_format`, `json.loads`, confidence(high/low).
- L4 **Solar 구조화 출력과 고르기**: 글에서 뽑을 땐 `solar-pro4` + `response_format`(strict), 파일·이미지에서 뽑을 땐 IE. 비용 비교.
- QB 헷갈림: IE vs 구조화 출력 / strict 규칙 / confidence 뜻.
- L5 **검증과 사람 확인**: 빠진 정답·형식 오류 검사, low만 교사가 확인, `questions.json`(트랙 A 채점 데이터). 연습장(py): 검증 함수.
- M1 내 학습지에서 문항 뽑기 → 스키마 두 번 고치며 정확도 기록 → questions.json → 검증 스크립트.

### c2u3 · 임베딩과 검색: 자료에서 근거 찾기 (1일차 15:00, 2일차 B 11:00 「자료 전처리와 검색 설계」)
- L1 **뜻으로 찾기**: 키워드 검색의 한계(동의어·풀어 쓴 질문), 임베딩 = 뜻을 숫자 목록으로, 가까우면 비슷.
- L2 **query vs passage**: 두 모델, 1,024차원, 100개씩, `embed.py`.
- QA 헷갈림: query vs passage / 차원 vs 토큰 / 임베딩 vs 생성.
- L3 **조각 나누기**: 제목 단위·길이 단위·겹치기, Document Parse 요소 활용, 메타데이터(파일·쪽·제목). 연습장(py): 겹치는 조각 함수.
- L4 **코사인 유사도와 top-k**: 연습장(py): 3차원 장난감 벡터로 코사인·정렬. `search.py`(벡터를 json에 저장, 순수 파이썬).
- QB 헷갈림: 코사인 vs 거리 / top-k 크기 / 조각 크기.
- L5 **검색 품질 점검**: 질문 10개 시험표, 못 찾을 때 고칠 곳(조각 크기·제목 붙이기·질문 다듬기), 비용이 아주 싸다.
- M1 수업자료 md → chunks.json → 임베딩 저장 → 질문 5개 검색 → 결과 표.

## 과정 3 · AI 수업도구 만들기

### c3u1 · 내 수업자료로 대답하는 보조 에이전트 (1일차 15:00 「나만의 보조 agent 제작」, 2일차 B 10:00 「문서 기반 챗봇 구조」)
- L1 **RAG 한눈에**: 준비(파싱→조각→임베딩) / 질문할 때(검색→프롬프트 조립→답). 왜 다시 학습(파인튜닝)이 아닌가, 자료가 짧으면 통째로 넣기도 된다(512K).
- L2 **프롬프트 조립**: 시스템 규칙("자료에 없으면 모른다고"), 근거 조각에 번호, 출처 표시. 연습장(py): 검색 결과로 messages 만들기.
- QA 헷갈림: 검색 vs 생성 / 시스템 규칙 vs 자료 / 통째로 넣기 vs RAG.
- L3 **helper.py 완성**: 검색 + Solar, 출처(파일·쪽), 비용·정확도 때문에 top-k만 넣는 이유.
- L4 **"보조 agent"의 정체**: 지금은 정해진 순서(워크플로), 대화 기록·후속 질문 다시 쓰기, 진짜 에이전트는 과정 5에서.
- QB 헷갈림: 워크플로 vs 에이전트 / 후속 질문 / 출처 표시.
- L5 **평가하기**: 질문 세트, 근거 맞나, "모른다"가 맞는 질문, 채점표, LLM으로 채점 맛보기.
- M1 helper.py로 수업자료 질의응답 → 출처 → 자료 밖 질문 시험 → 에이전트에게 정리 부탁.

### c3u2 · 수업 도구의 4요소와 제작 절차 (1일차 11:00 「사례 시연과 제작 절차」·16:00 「4요소」, 2일차 14:00)
- L1 **AI 수업도구 사례**: 질문 도우미·자동채점·퀴즈 생성·피드백·자료 요약 — 각각 어느 API를 쓰나.
- L2 **4요소**: 학생활동·교사의 할·자료·평가. 연습장(md): 4요소 기획 캔버스 쓰기.
- QA 헷갈림: 학생활동 vs 교사의 할 / 자료 vs 평가 / 도구 vs 수업.
- L3 **제작 절차**: 문제 정의 → 4요소 설계 → 작은 시제품(터미널) → 화면 → 시범 → 고치기. 에이전트 코딩으로 빠르게(Plan → 작게 → 확인).
- L4 **Streamlit 화면**(모의 화면: 웹 창 `localhost:8501` 챗봇): `st.chat_input`, `st.chat_message`, `st.session_state`, `streamlit run app.py`, 키는 서버 쪽에만.
- QB 헷갈림: `session_state` / `streamlit run` vs `python` / 학생 화면 vs 교사 화면.
- L5 **수업에 넣기**: 도입·전개·정리 어디에, 기록 보기, 평가 연결, 학교 네트워크·기기·지침 확인, 배포는 학교 지침에 따라.
- M1 4요소 기획서 → helper를 Streamlit 앱으로 → 동료에게 시범 → 피드백 기록.

### c3u3 · AI 챗봇의 교실 안전장치 (1일차 17:30, 2일차 16:00)
- L1 **교실의 위험**: 개인정보, 부적절한 답, 환각, 프롬프트 인젝션, 과의존·대리 숙제, 비용 폭주. 교육 당국 지침(`context.md` 근거)과 학교 규정 먼저.
- L2 **겹겹이 막기**: 입력 검사 → 시스템 프롬프트 → 출력 검사 → 기록·교사 확인. 연습장(md): 안전 규칙 시스템 프롬프트.
- QA 헷갈림: 입력 검사 vs 출력 검사 / 시스템 프롬프트의 한계 / 기록 vs 감시.
- L3 **입력 안전장치 guard.py**: 개인정보 가리기(전화번호 모양 등 문자열 검사), 금칙어, 길이 제한, Solar로 분류(구조화 출력 `{safe, reason}`). 연습장(py): 문자열 검사 함수.
- L4 **출력 안전장치와 인젝션**: "이전 지시 무시", 자료 속 숨은 지시, 출력 검사, 정답 통째로 알려 주지 않기.
- QB 헷갈림: 인젝션 vs 탈옥 / 자료 속 지시 / 거절 vs 안내.
- L5 **운영 안전장치**: 학생당 횟수 제한, 429 대비, 비용 상한·크레딧 확인, 로그와 교사 확인, 학생·학부모 안내, 사고가 나면.
- M1 guard.py 붙이기 → 공격 질문 10개 시험(레드팀) → 결과 기록 → 안전 규칙 문서.

## 과정 4 · 2일차 트랙 A 실습

배우는 사람은 **트랙 A 반**이다. 과정 4는 트랙 A(파이썬 자동채점 + AI 튜터)를 세 단원으로 깊게 다루고, 트랙 B는 선택 단원(c4u4) 하나로 엿보기만 한다.

### c4u1 · 트랙 A ① 파이썬 자동채점 (2일차 A 09:00~12:00 「자동채점 기초·로직 설계·문제·정답 데이터」)
- L1 **자동채점의 종류**: 정답 비교, 테스트 케이스 실행, 루브릭(LLM) 채점. 자동으로 할 것과 사람이 할 것.
- L2 **채점 로직 설계**: 입력·출력 테스트 케이스, 공백·대소문자 정리, 부분 점수. 연습장(py): 채점 함수.
- QA 헷갈림: 정답 비교 vs 테스트 케이스 / 부분 점수 / 정리(normalize).
- L3 **문제·정답 데이터**: `problems.json` 모양(id, 문제, 함수 이름, 테스트 케이스, 배점, 힌트), c2u2 IE로 만든 questions.json 잇기. 연습장(py): json 다루기.
- L4 **학생 코드 실행**: 함수 호출 채점, 표준 입출력 채점, 시간 제한(subprocess timeout), 위험한 코드(무한 반복·파일 지우기) — 안전 실행 원칙(설명 code로).
- QB 헷갈림: exec vs subprocess / timeout / 표준 입출력.
- L5 **채점 리포트**: 점수표, 틀린 케이스 보여 주기, CSV, 교사 확인. 연습장(py).
- M1 grader/ 만들기: problems.json 3문제, grade.py, 학생 답안 5개 채점, 결과 CSV.

### c4u2 · 트랙 A ② AI 튜터와 자동채점 잇기 (2일차 A 13:00~17:30 「AI튜터 대화 흐름·수업 활동 연결·안전장치」)
- L1 **AI 튜터 대화 흐름**: 정답 대신 힌트 단계(개념 → 위치 → 예시), 학생이 먼저 시도. 연습장(md): 튜터 시스템 프롬프트.
- L2 **채점 결과를 튜터에게**: 실패한 테스트 케이스 + 학생 코드로 맞춤 힌트. 연습장(py): 프롬프트 조립.
- QA 헷갈림: 힌트 vs 정답 / 채점 결과 넘기기 / 단계 올리기.
- L3 **tutor.py**: 힌트 단계 세기, 구조화 출력 `{level, message}`, 정답 코드가 새어 나가는지 검사.
- L4 **수업 활동과 잇기**: 언제 채점·튜터를 쓰나, Streamlit 화면(코드 입력 → 채점 → 힌트), 교사 화면.
- QB 헷갈림: 학생 화면 vs 교사 화면 / 기록 / 힌트 횟수 제한.
- L5 **AI 튜터 안전장치**: "답만 줘", 대리 과제, 감정·위기 신호는 교사에게, 기록.
- M1 튜터 + 채점기 앱 → 학생 역할로 10번 시험 → 안전 시험.

### c4u3 · 트랙 A ③ 연수 실습 완주: 자동채점 + AI 튜터 (2일차 A 15:00 「파이썬 자동채점 + AI튜터」, 16:00 「AI튜터 안전장치 적용」)
- L1 **연수 당일 실습 지도**: 2일차 트랙 A 7차시를 시간표대로 따라가며 무엇을 만들고 무엇을 미리 준비할지(템플릿 폴더, problems.json 3문제, `.env`, 핫스팟), 연수장에서 자주 막히는 곳(가상 환경, 키, 429, 경로)과 바로 푸는 법.
- L2 **Solar로 테스트 케이스 늘리기**: 구조화 출력으로 경계 케이스 후보를 받고, **교사의 정답 코드로 돌려 expected를 사람이 확정**(LLM이 정답을 정하지 않게). 연습장(py): 후보 케이스를 정답 함수로 검증해 틀린 expected 걸러 내기.
- QA 헷갈림: 테스트가 정하는 것 vs LLM이 돕는 것 / 경계 케이스 / 정답 코드 공개.
- L3 **루브릭 피드백**: 테스트로 못 보는 것(이름 짓기·중복·주석·효율)을 루브릭 JSON으로, **점수는 테스트로만, LLM은 서술 피드백만**(공정성·일관성), temperature 낮게, 같은 코드 두 번 돌려 흔들림 확인.
- L4 **반 전체 결과로 수업 고치기**: 결과 모으기, 많이 틀린 케이스·오답 유형, 힌트 단계 분포, 교사 화면(Streamlit) — 다음 차시 수업 계획으로. 연습장(py): 반 결과 집계.
- QB 헷갈림: 점수 vs 피드백 / 개인 기록 vs 반 통계 / 캐시.
- L5 **교실에서 굴리기**: 30명이 한 키로 동시에(429, 줄 세우기, 같은 실패에는 같은 힌트 재사용), 비용 어림, 기록·개인정보 최소화, 학생 안내문, 연수 발표용 정리(→ c5u3 대회).
- M1 집에서 연수 실습을 한 번 완주: grader + tutor + 루브릭 + 교사 화면, 학생 역할 시험 10번, 비용 기록, 연수 당일 체크리스트 완성.

### c4u4 · (선택) 트랙 B 엿보기: 자료 기반 AI 학습 챗봇 (2일차 B 09:00~17:30)
- L1 **기획**: 대상·자료·질문 유형·답 방식(근거·출처·수준), 4요소 적용.
- L2 **문서 기반 챗봇 구조**: Parse → 조각 → 임베딩 → 색인 → 검색 → 답, 품질을 좌우하는 곳.
- QA 헷갈림: 색인 vs 검색 / 메타데이터 / 다시 색인.
- L3 **전처리와 검색 설계**: 단원·쪽 메타데이터, 표·그림 처리, 키워드+임베딩 섞기, top-k. 연습장(py): 섞은 점수.
- L4 **답변 흐름**: 질문 분류(자료 질문·잡담·위험) → 검색 → 답 + 출처 → 이해 확인 질문, 학생 수준 맞추기.
- QB 헷갈림: 분류 단계 / 출처 / 수준 맞추기.
- L5 **학습자료 연결과 안전장치**: 새 자료 추가 절차, Streamlit 앱, 자료 밖 질문·인젝션 막기, 평가표.

## 과정 5 · 에이전트와 대회

### c5u1 · 도구를 쓰는 에이전트
- L1 **워크플로 vs 에이전트**: 정해진 순서 vs 모델이 다음 행동을 고름, 루프(요청 → 도구 → 결과 → 반복).
- L2 **tools 정의**: JSON Schema 매개변수, 설명이 중요, `tool_choice`.
- QA 헷갈림: tool_calls vs content / auto vs required / 함수 실행은 누가.
- L3 **agent.py 루프**: FACTS 4절 순서, 호출마다 결과, `content` None 처리, 최대 턴. 연습장(py): 흉내 낸 응답으로 루프 돌리기.
- L4 **수업 에이전트 도구 설계**: `search_materials`(RAG), `grade_code`(트랙 A), `make_quiz`(구조화 출력), 위험한 도구는 안 주기(최소 권한), 사람 확인 단계.
- QB 헷갈림: 최소 권한 / 확인 단계 / 도구 설명.
- L5 **MCP와 Studio**: Upstage MCP 서버(`parse_document`, `extract_information`)를 Cursor에 연결해 에이전트가 문서를 직접 읽게(모의 화면), Upstage Studio(노코드 문서 에이전트) 소개.
- M1 agent.py 도구 3개 → 과제 10개 시험 → Cursor에 mcp-upstage 연결 → 수업자료 요약 시키기.

### c5u2 · 멀티에이전트: 역할 나누기
- L1 **왜 여럿으로 나누나**: 역할 분리(출제·검토·채점), 짧고 분명한 지시, 서로 검사. 하나로 충분할 때가 많다(비용·복잡도).
- L2 **패턴**: 순차 파이프라인, 감독자-작업자, 만들기-검토 반복, 나눠 하고 합치기.
- QA 헷갈림: 파이프라인 vs 감독자 / 검토 반복 끝내기 / 병렬.
- L3 **team.py 출제 팀**: 출제 → 검토(구조화 출력 `{pass, issues}`) → 고치기(최대 2번) → 확정. 연습장(py): 흉내 낸 검토로 반복.
- L4 **감독자 에이전트**: 하위 에이전트를 도구처럼 부르기, 상태(JSON) 공유, 로그, 모델 나눠 쓰기(작업자 `solar-mini4`, 감독자 `solar-pro4`).
- QB 헷갈림: 상태 공유 / 모델 나눠 쓰기 / 로그.
- L5 **평가와 비용**: 토큰 어림, 실패 모양(끝없는 반복·맞장구), 사람 확인, 커서한입의 서브에이전트와 같은 생각.
- M1 team.py로 형성평가 10문제 + 검토 로그 → 비용 계산.

### c5u3 · 대회 준비: 공모전과 해커톤
- L1 **대회 종류와 심사 기준**: 공모전형(기획·교육적 효과·적용 가능성·확산성), 해커톤형(완성도·기술·창의성·발표). 근거는 `context.md`, 없으면 "공고문의 심사 기준을 먼저 읽어요".
- L2 **아이디어와 문제 정의**: 현장 문제, 차별점, 4요소, 한국어 자료·소버린 AI의 강점. 연습장(md): 한 장 기획서.
- QA 헷갈림: 기능 vs 문제 / 차별점 / 대상.
- L3 **빠르게 만들기(해커톤)**: MVP 범위, 에이전트 코딩 흐름(Plan → 작게 → 확인), 미리 준비할 것(템플릿 저장소, `.env`, 데모 자료), 시간 나누기.
- L4 **증거 만들기(공모전)**: 수업 적용 기록, 학생 반응·평가(개인정보 없이), 전후 비교, 보고서 구조.
- QB 헷갈림: 데모 vs 증거 / MVP / 확산성.
- L5 **발표와 시연**: 3분 데모 대본, 실패 대비(녹화본·오프라인 대체), 질문 대비(안전·비용·확산), README·GitHub 정리.
- M1 내 대회 계획: 기획서 1장 → MVP 기능 3개 → 데모 대본 → README → 연습 발표 녹화.
